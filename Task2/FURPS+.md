# Архитектурно-значимые требования для MVP открытия депозитов

| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| **F**   | **Функциональные (Functionality)**     |              |
| F1  | Отображение списка депозитов с актуальными ставками на сайте для новых клиентов |  |
| F2  | Подача заявки на депозит с сайта (ФИО + телефон) для новых клиентов |  |
| F3  | Отображение списка депозитов с актуальными и персонализированными ставками в интернет-банке |  |
| F4  | Подача заявки на депозит в интернет-банке (счет + сумма) с подтверждением по СМС |  |
| F5  | Управление ставками по депозитам сотрудниками бэк-офиса депозитов и кредитов |  |
| F6  | Обработка и согласование заявок менеджерами бэк-офиса в АБС (MVP) |  |
| F7  | Отправка СМС-уведомлений клиенту после подтверждения ставки и открытия депозита |  |
| F8  | Передача заявок из системы кол-центра в АБС для обработки |  |
| F9  | Кэширование справочных данных для ускорения загрузки | Дополнительное требование: текущая проблема - загрузка справочников >1 сек при платежах, необходимо оптимизировать |
| **U**   | **Удобство использования (Usability)** |              |
| U1  | Максимально удобный интерфейс для клиента |  |
| U2  | Соблюдение системы дизайна компании (брендинг, цвета, элементы) |  |
| U3  | Интуитивно понятный процесс подачи заявки (минимум шагов) | Дополнительное требование: упрощение процесса повысит конверсию и снизит нагрузку на кол-центр |
| U4  | Понятные сообщения об ошибках и статусе обработки заявки | Дополнительное требование: клиент должен понимать, на каком этапе находится его заявка |
| **R**   | **Надёжность (Reliability)**           |              |
| R1  | Доступность сервисов 24/7 с uptime 99.9% (SLA) |  |
| R2  | Переключение на резервный ЦОД в случае сбоя основного |  |
| R3  | Избежание прямой работы интернет-банка с API АБС в реальном времени |  |
| R4  | Горизонтальное масштабирование компонентов интернет-банка и распределение нагрузки |  |
| R5  | Защита от потери данных заявок клиентов | Дополнительное требование: заявки - критичные данные, должны сохраняться даже при сбоях |
| **P**   | **Производительность (Performance)**   |              |
| P1  | Время отклика по всем операциям - миллисекунды |  |
| P2  | Поддержка увеличенной нагрузки от онлайн-каналов без деградации АБС |  |
| P3  | Масштабирование под растущее количество пользователей онлайн-каналов |  |
| P4  | Вертикальное масштабирование АБС |  |
| P5  | Асинхронная обработка тяжелых операций | Дополнительное требование: расчет персональных ставок, отправка СМС не должны блокировать UI |
| **S**  | **Поддерживаемость (Supportability)**  |              |
| S1  | Использование существующих технологий банка (MS SQL, Oracle) |  |
| S2  | Совместимость новых технологий с существующими платформами разработки |  |
| S3  | Разработка документации API для дальнейшего расширения системы |  |
| S4  | Использование Apache Kafka для очередей сообщений (на перспективу) |  |
| S5  | Переход интернет-банка на микросервисную архитектуру (начать с депозитов) |  |
| S6  | Избежание доработок ядра интернет-банка подрядчиком |  |
| S7  | Логирование и мониторинг всех операций | Дополнительное требование: необходимо для диагностики проблем и аудита |
| S8  | Модульная архитектура для повторного использования компонентов | Дополнительное требование: решение для депозитов должно быть применимо для кредитов в будущем |
| **+R**  | **+ Ограничения (Restrictions)**       |              |
| +R1 | Шифрование трафика между сайтом и бэкенд-системами |  |
| +R2 | Шифрование трафика между интернет-банком и бэкенд-системами |  |
| +R3 | Несовместимость текущей версии интернет-банка (ASP.NET MVC 4.5 / .NET 4.5) с Kafka |  |
| +R4 | Невозможность горизонтального масштабирования АБС (только вертикальное) |  |
| +R5 | Требования безопасности: разделение доступа бэк-офиса депозитов и кредитов к данным |  |
| +R6 | Новые клиенты должны пройти идентификацию в отделении |  |
| +R7 | Монолитная архитектура интернет-банка на платформе подрядчика |  |
| +R8 | Решение должно быть реализуемо за 6 месяцев |  |
| +R9 | Совместимость с существующей инфраструктурой ЦОД (основной + резервный) |  |
